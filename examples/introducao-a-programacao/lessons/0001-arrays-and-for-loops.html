Arrays and for loops

By the end of this lesson you can create a Java array, fill and read it with a for loop, and avoid the two bugs that crashed Lab 1: an array that was declared but never created, and a loop that runs one step too far.

The idea

An array is a fixed-size, ordered block of variables of the same type. Declaring an array variable and creating the array are two different steps — this is exactly where Lab 1's crash came from.

Two consequences follow directly from that picture:

  • Valid indices run from 0 to length - 1, never up to length. A 4-slot array has indices 0, 1, 2, 3 — scores[4] does not exist.
  • A freshly created array is not empty — it is full of default values: 0 for numeric types, false for boolean, and null for object types such as String.

To get the size of an array, read its length field — no parentheses, because it is a field, not a method (unlike String's .length()):

int size = scores.length;

A for loop has three parts, each doing one job:

for (int i = 0; i < scores.length; i++) {
    // body runs once per value of i
}

int i = 0 runs once, before the loop starts. i < scores.length is checked before every iteration; the loop stops the moment it is false. i++ runs after every iteration. Using scores.length as the bound — instead of a hard-coded number — is what keeps the loop correct even if the array's size changes.

Worked example

Fill a 4-slot array of temperatures, then sum it with a second loop:

double[] temps = new double[4];
temps[0] = 21.5;
temps[1] = 19.0;
temps[2] = 23.5;
temps[3] = 20.0;

double total = 0;
for (int i = 0; i < temps.length; i++) {
    total += temps[i];
}

Tracing the second loop, one row per iteration:

stepii < temps.length?temps[i]total after
100 < 4 → yes21.521.5
211 < 4 → yes19.040.5
322 < 4 → yes23.564.0
433 < 4 → yes20.084.0
544 < 4 → no, stop—84.0

Step 5 never touches temps[4] — that index does not exist. That is the whole purpose of < instead of <= in the condition.

Practice

1. What does this print?

int[] arr = new int[4];
for (int i = 0; i < arr.length; i++) {
    arr[i] = i * 2;
}
System.out.println(arr[3]);

arr[3] was set when i == 3, so it holds 3 * 2 = 6. arr has indices 0–3, so i stops at 3.

2. Right after int[] arr = new int[5];, before any assignment, what is arr[2]?

new int[5] creates 5 slots and fills every one with the default value for int, which is 0. Java always initialises a new array; it never leaves slots with leftover memory.

3. int[] arr = new int[n]; — which loop header visits every valid index and never goes out of bounds?

Valid indices are 0 to n - 1. Option 1 reaches i == n, one past the last valid index — this is the exact bug that crashed Lab 1. Option 3 skips index 0.

4. What happens when this runs?

static String[] names;

public static void main(String[] args) {
    names[0] = "Ana";
}

names is a field that is never assigned with new, so it holds null — the compiler cannot catch this, only the JVM can, at run time, the moment you try to index into it. This is exactly Lab 1's row-1 bug: allocate the array with new before indexing into it.
