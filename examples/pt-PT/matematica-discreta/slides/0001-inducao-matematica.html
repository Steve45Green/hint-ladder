Indução matemática (fraca e forte)

No fim consegues escrever, sozinho, uma prova por indução — fraca ou forte — completa, sem confundir hipótese com tese.

Esta é a base de toda a Matemática Discreta: quase todas as provas sobre naturais, sucessões e recorrências passam por aqui. O Teste 1 (2026-11-05) inclui indução; o objetivo deste estudo é escrever uma prova que um corretor não consiga contestar.

Porque precisamos de indução

  • Testar caso a caso nunca acaba: há infinitos naturais — não podemos verificar P(1), P(2), P(3)… um a um.
  • A indução prova P(n) para todos os n de uma vez: um caso base + um argumento que se repete indefinidamente.
  • Analogia: uma fila infinita de dominós. Basta (1) empurrar o primeiro e (2) garantir que cada um, ao cair, derruba o seguinte.
A ideia central: em vez de verificar infinitos casos, verificamos duas coisas finitas — o caso base, e que o padrão "se funciona aqui, funciona no próximo" se mantém sempre. Isso substitui um número infinito de verificações por duas.

Princípio da indução fraca

Para provar P(n) para todo n ≥ n₀:

  1. Base: P(n₀) é verdadeira.
  2. Passo indutivo: para todo k ≥ n₀, se P(k) é verdadeira então P(k+1) é verdadeira.

Conclusão: P(n) verdadeira para todo n ≥ n₀.

Fonte: Rosen, Discrete Mathematics and Its Applications, cap. 5 (Indução e Recursão).

O nome "fraca" não significa "menos válida" — significa apenas que o passo indutivo só pode usar P(k), o vizinho imediato, para provar P(k+1). Repara que k é um natural fixo mas arbitrário: a prova do passo tem de funcionar para qualquer k, não para um k específico.

Exemplo resolvido (fraca)

Provar que, para todo n ≥ 1: 1+2+⋯+n = n(n+1)/2

Base (n = 1): 1 = 1·2/2 = 1 ✓Hipótese P(k): 1+2+⋯+k = k(k+1)/2Queremos P(k+1): 1+2+⋯+k+(k+1) = (k+1)(k+2)/21+2+⋯+k+(k+1) = k(k+1)/2 + (k+1)   [usa a hipótese]= (k+1)·(k/2 + 1) = (k+1)(k+2)/2 ✓

Fonte: Rosen, Discrete Mathematics and Its Applications, cap. 5.1, exemplo clássico da soma dos n primeiros naturais.

A linha destacada é o único sítio onde a hipótese de indução é realmente usada — é aí que trocamos "1+2+⋯+k" por "k(k+1)/2", porque assumimos P(k) verdadeira. Sem essa substituição não há indução, é só álgebra. A partir daí é fatorizar (k+1) e comparar com a tese.
Verifica-te · 1

Na prova acima, qual é exatamente a hipótese de indução — nem mais, nem menos?

P(k): "1+2+⋯+k = k(k+1)/2", para um k ≥ 1 fixo mas arbitrário. Nunca é P(n) (o que queremos provar no geral) nem P(k+1) (a tese do passo) — assumir P(k+1) seria dar como provado aquilo que se quer provar.

Este é o erro mais comum em exame: escrever "assumo P(k+1)" ou confundir a hipótese com a tese. A hipótese é sempre sobre o caso anterior, k; a tese do passo é sobre k+1, e é isso que a prova tem de derivar — sem assumir.

Erros comuns que um corretor rejeita

  • Esquecer o caso base — sem ele, o passo indutivo prova algo que pode nunca ter começado.
  • Assumir P(k+1) em vez de P(k) — é circular, não é uma prova.
  • Escrever a hipótese e nunca a usar no passo — se a demonstração de P(k+1) não usa P(k), não é indução.
  • Indexar mal: começar a base no n errado, ou deixar k variar fora do domínio de P.
Antes de entregar uma prova por indução, faz sempre esta checklist: (1) o caso base está lá e está correto; (2) a hipótese está escrita explicitamente e só fala de k; (3) a linha onde a hipótese é usada está identificada; (4) a conclusão fecha citando o princípio de indução.

Quando a fraca não chega

  • Às vezes provar P(k+1) exige P(a) e P(b) com a,b < k+1 — mas a e b não são necessariamente k. Ex.: se k+1 = a·b, os fatores a e b podem ser muito menores do que k.
  • Outro caso clássico: sucessões definidas por recorrência com mais de um termo anterior (ex.: F(n) = F(n−1) + F(n−2)). Uma propriedade de F(n) pode depender de dois termos anteriores, não só do "vizinho" imediato.
  • Precisamos de uma hipótese mais generosa: assumir todos os casos anteriores, não só o último.

Este ponto liga diretamente ao tema seguinte do programa: Relações de recorrência.

A indução fraca não está errada nestes casos — é só insuficiente na forma como a hipótese está escrita. A solução não é abandonar a indução, é fortalecer a hipótese: em vez de "assumo só P(k)", assumo "P(n₀) e P(n₀+1) e … e P(k)", tudo o que já foi estabelecido até k.

Princípio da indução forte

Para provar P(n) para todo n ≥ n₀:

  1. Base: P(n₀) verdadeira (e P(n₀+1), … se o passo precisar de mais do que um caso).
  2. Passo indutivo forte: para todo k ≥ n₀, se P(n₀), P(n₀+1), …, P(k) são todas verdadeiras, então P(k+1) é verdadeira.

Conclusão: P(n) verdadeira para todo n ≥ n₀.

Fonte: Rosen, Discrete Mathematics and Its Applications, cap. 5.2 (Strong Induction).

Fraca e forte são logicamente equivalentes — provam exatamente as mesmas afirmações, porque uma hipótese forte inclui a fraca como caso particular e pode ser derivada dela. A diferença é só de conforto: a forte dá-te mais material para trabalhar dentro do passo, o que é essencial quando o passo precisa de um caso que não é k.
Verifica-te · 2

Qual é, exatamente, a diferença entre a hipótese da indução fraca e a da indução forte?

Fraca: assume só P(k). Forte: assume P(n₀), P(n₀+1), …, P(k) — todos os casos desde a base até k. A forte contém a fraca como caso particular (podias sempre optar por só usar P(k) lá dentro); usa-se quando o passo precisa de um caso anterior que não é k.

Um erro comum é achar que a indução forte "prova mais coisas" do que a fraca — não é verdade, são equivalentes em poder lógico. A forte só é mais prática de escrever quando o argumento do passo precisa de casos que não são o imediatamente anterior.

Exemplo resolvido (forte)

Provar que todo n ≥ 2 é produto de um ou mais primos.

Base (n = 2): 2 é primo, logo já é "produto" de um fator ✓Hipótese forte: todo i com 2 ≤ i ≤ k é produto de primosCaso A — k+1 é primo: é o próprio único fator ✓Caso B — k+1 composto: k+1 = a·b, com 2 ≤ a,b ≤ kPor hipótese, a e b são produto de primos ⟹ k+1 = a·b também ✓

Fonte: Rosen, Discrete Mathematics and Its Applications, cap. 5.2 — existência na fatorização em primos (Teorema Fundamental da Aritmética).

O ponto crucial está na linha destacada: k+1 = a·b, e a e b são ambos menores que k+1 (porque nenhum fator próprio de um número composto pode ser igual ou maior que ele), mas não sabemos se são iguais a k — podem ser qualquer valor entre 2 e k. Só por isso é preciso a hipótese forte: a fraca (só P(k)) não cobre a e b em geral.
Verifica-te · 3

Porque não bastava a hipótese fraca (só P(k)) na prova de que todo n ≥ 2 é produto de primos?

Porque no caso composto, k+1 = a·b, os fatores a e b são menores do que k+1 mas não são necessariamente iguais a k — podem ser qualquer valor entre 2 e k. A hipótese fraca só te dá P(k); a hipótese forte dá-te P(a) e P(b) para quaisquer a,b nesse intervalo, que é exatamente o que o passo precisa.

Repete este raciocínio em voz alta antes de veres a resposta: é o padrão que aparece sempre que a indução forte é necessária — o passo depende de um valor "algures lá atrás", não do vizinho imediato.

Não há "melhor" — há a que se escreve mais naturalmente para o problema em mãos. Em exame, escolhe a forte assim que sentires necessidade de usar um caso que não é k; caso contrário, a fraca é mais direta e mais curta de escrever.

Resumo

  • Indução fraca: base + "P(k) ⟹ P(k+1)". Indução forte: base + "P(n₀),…,P(k) ⟹ P(k+1)" — equivalentes, a forte só dá mais para trabalhar no passo.
  • O erro que mais reprova em exame: assumir a tese em vez da hipótese, ou nunca usar a hipótese no passo.
  • Este princípio é a base do próximo tema do programa — Relações de recorrência — onde quase todas as provas são por indução forte.
