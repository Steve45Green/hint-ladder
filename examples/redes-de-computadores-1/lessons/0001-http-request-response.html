HTTP: the request/response structure

By the end of this lesson you can read a raw HTTP request or response — the kind Wireshark shows inside a TCP stream — and name its method, status code and class without notes.

The idea

HTTP is a text-based, stateless request/response protocol. "Stateless" means the server treats every request on its own: nothing about one request is remembered for the next, unless the application adds cookies or a session token on top. HTTP itself runs inside a TCP connection — TCP moves the bytes reliably; HTTP is just the text format those bytes carry (RFC 9110).

A request has three parts: a request line (method, path, version), headers (one per line, Name: value), and an optional body. A response mirrors it: a status line (version, status code, reason phrase), headers, then an optional body. Status codes fall into five classes by their first digit:

ClassMeaningExample
1xxinformational100 Continue
2xxsuccess200 OK
3xxredirection301 Moved Permanently
4xxclient error404 Not Found
5xxserver error503 Service Unavailable

Worked example

A browser asking for a page:

GET /index.html HTTP/1.1
Host: example.org
Accept: */*

And the server's reply:

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 138

<html>...</html>
LineTextWhat it means
Request lineGET /index.html HTTP/1.1Method GET, path /index.html, version HTTP/1.1

Practice

1. A capture shows this as the first line of a request:

POST /login HTTP/1.1

Which HTTP method is being used? (one word, capitals)

The method is always the first word of the request line — here POST, used to submit data such as a login form.

2. A server replies with status code 503. Name its class: informational, success, redirection, client-error or server-error?

The first digit, 5, marks a server-error: the server itself failed to fulfil a valid request (here, it was unavailable).

3. In a raw HTTP request, which line always comes first?

The request line (method, path, version) always opens the request; headers follow, then a blank line, then the optional body.

4. Without cookies or a session token, does a plain HTTP server remember your previous request?

HTTP is stateless: on its own, the server treats every request independently. Applications add cookies or tokens on top to fake memory.
